# StackScript fork plan

Reference: Hideki's original StackScript 1059555
(https://cloud.linode.com/stackscripts/1059555), mirrored at
https://github.com/hokamoto/elasticsearch-kibana-for-akamai-datastream2.

**State of the upstream (checked 2026-10-09):** Hideki is actively
maintaining the script. Last update 2026-08-31 (rev note: "Support Index
Lifecycle Management"), 717 total deploys / 84 active. The upstream already
covers Elasticsearch 8.x, a CMCD ingest pipeline, a breadcrumbs ingest
pipeline, an ILM policy, and dashboards with lookup formatters. The gap
between upstream and 2026-ideal is smaller than this file originally
assumed, revised below.

Goal of the fork: keep the two-field UDF experience (credentials + ES/Kibana
admin) and the 10-minute wall clock, but close the gaps that upstream has
not shipped: newer base image, security dataset mappings (Bot Manager,
Account Protector, API Protector), snapshot repo to Object Storage, and
optional HTTPS via Let's Encrypt.

## Diff summary

| Area | Upstream (Aug 2026) | Forked (2026-10 proposal) |
|------|---------------------|---------------------------|
| Base image | Ubuntu 22.04 | Ubuntu 24.04 LTS |
| Elasticsearch | 8.x | 8.x pinned, 9.x opt-in var |
| Kibana | same as ES | same as ES |
| HTTP TLS | disabled by script | opt-in Let's Encrypt via UDF (certbot --standalone) |
| Node sizing hint | 8 GB | 8 GB minimum, surface 16/32 GB preset in UDF |
| Index template | CDN + CMCD + breadcrumbs | add Bot Manager, Account Protector, API Protector, TLS early data fields |
| Data views | one, `datastream2*` | split: `datastream2-cdn-*`, `datastream2-sec-*`, `datastream2-ew-*` |
| Dashboards | CDN + CMCD video | add Security (WAF + Bot + AP), API Protector |
| ILM | rollover 30d / 50 GB (hot only) | add warm/cold phases, snapshot to Object Storage |
| Firewall | script does basic ufw | no change (TF module handles firewall now) |
| Snapshots | none | Object Storage snapshot repo configured if S3 creds UDF present |

## UDF additions

- `ES_VERSION` (default `8.15`, allow `9.x`)
- `OBJECT_STORAGE_BUCKET` + `OBJECT_STORAGE_ACCESS_KEY` + `OBJECT_STORAGE_SECRET` (optional, enables snapshot repo)
- `ENABLE_LETS_ENCRYPT` (bool, default off)
- `PUBLIC_HOSTNAME` (needed when LE is on)
- `DS2_INGEST_USER`, `DS2_INGEST_PASSWORD` (kept)

## Package install sequence

1. apt update, install `openjdk-21-jre-headless`, `jq`, `curl`, `nginx`, `certbot`.
2. Add Elastic apt repo for the selected major.
3. Install `elasticsearch`, `kibana`.
4. Patch `elasticsearch.yml`: `xpack.security.enabled: true`, `xpack.security.http.ssl.enabled: true` (self-signed CA generated by script into `/etc/elasticsearch/certs`).
5. If `ENABLE_LETS_ENCRYPT=true`: `certbot --standalone -d $PUBLIC_HOSTNAME`, then replace HTTP cert.
6. Set `elastic` admin password with `elasticsearch-reset-password`.
7. Create ingest role `ds2_ingest` with `create`, `write` on `datastream2-*`.
8. Create user `DS2_INGEST_USER` with that role.
9. Start kibana, generate enrollment token, write kibana.yml, start.
10. POST index templates, lifecycle policy, snapshot repo if credentials given.
11. Import `kibana/export.ndjson` with `curl -XPOST /api/saved_objects/_import`.
12. If Cloud Firewall API available: pre-stage inbound rules allowing DS2 IP ranges on 9200/443.

## Index template highlights

- Index pattern: `datastream2-cdn-*`.
- Lifecycle policy: `datastream2-cdn`, hot rollover at 50 GB or 1 day.
- Mapping notes:
  - `cp` as keyword.
  - `botScore` as byte or short.
  - `cmcd_*` as its own object with mixed types; booleans for `cmcd_bs`, `cmcd_su`, integers for `cmcd_br`, `cmcd_mtp`, `cmcd_dl`, keywords for `cmcd_cid`, `cmcd_sid`, `cmcd_sf`, `cmcd_ot`.
  - `securityRules` as keyword with `ignore_above: 4096`.
  - `apiSummary` as object with `ignore_malformed: true`.
  - `ewExecutionInfo`, `ewUsageInfo` as `flattened`.
- Component templates split: `datastream2-base`, `datastream2-cmcd`, `datastream2-security`, `datastream2-ew`.

## Snapshot repo

If Object Storage creds are provided, register an S3 repository:

```json
PUT _snapshot/akamai_object_storage
{
  "type": "s3",
  "settings": {
    "bucket": "{{OBJECT_STORAGE_BUCKET}}",
    "endpoint": "{{REGION}}.linodeobjects.com",
    "access_key": "{{OBJECT_STORAGE_ACCESS_KEY}}",
    "secret_key": "{{OBJECT_STORAGE_SECRET}}"
  }
}
```

Then an SLM policy that snapshots `datastream2-*` daily to that repo, keeping 30 days.

## When to NOT use this StackScript

- Any production load. Use LKE + ECK operator, or Elastic Cloud. Easier upgrades, HA out of the box.
- Multi-tenant stacks. Separate per-tenant indices and role-based access via Elastic Security.
- Compliance-sensitive data residency. Pin to a region that matches your obligations; Akamai Cloud Object Storage endpoint has to match.

## Alternative: Marketplace one-click

The Akamai Cloud Marketplace ships generic Elasticsearch and Kibana apps. Pros: upstream-flavored install, fewer custom moving parts, upgrade path is Elastic's. Cons: no DS2-specific templates or dashboards. The import step at the end of the blog post covers that gap.
